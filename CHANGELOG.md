# Changelog

## 1.0.0 — unpublished release candidate

- Added the Stage H cumulative hardening gate with a closed findings ledger, item-9 versus publication modes, bounded phase logs, clean-tree authority, deterministic double builds, reusable archive verification, extracted-source replay, exact Composer lock/install verification, current advisory evidence, and optional artifact-first WooCommerce promotion. Publication-only infrastructure failures are recorded separately and can never be presented as a source-code pass.
- Resolved hardening findings in request and administration boundaries: rejected negative or contradictory body lengths before memory admission, sanitized display-only administrator query values before use, canonicalized WooCommerce session-cookie values through the same `wp_unslash`/`wc_clean` boundary used by core, and corrected public-contract definition typing.
- Removed duplicated commerce policy by introducing one `CartQuantity` authority for integer/epsilon/maximum rules and one `ProductPriceRange` authority for recommendation and catalog price semantics. Added direct unit and regression coverage and no-growth maintainability budgets before the item-9 clarification rewrite.
- Reduced reviewed pre-release debt without broadening suppressions: PHPStan core from 113 to 111, PHPStan adapters from 179 to 140, and PHPCS/WPCS from 4,228 to 1,175; PHP 7.4 compatibility and ESLint remain at zero. Every remaining local suppression is path-, marker-, count-, and rationale-bound.
- Established the Stage G engineering baseline with exact Composer and npm development locks, PHPUnit 9, PHPStan, PHPCS with WordPress rules, PHPCompatibilityWP for PHP 7.4+, ESLint, source-layer/declaration checks, and package metadata verification. Production runtime remains Composer-dependency-free and development tools are excluded from the installable archive.
- Decomposed the 660 KB historical PHP test runner into ten subsystem case files behind a small compatibility entry point executed by PHPUnit; split widget unit coverage into seven subsystem files and Playwright coverage into five independently discovered specifications without dropping existing cases.
- Added explicit shrinking debt ledgers instead of blanket exclusions: PHPStan core level 8 and adapter level 6 findings are message/path/count-bound, PHPCS debt is file/sniff/type/count-bound, PHP compatibility and ESLint remain zero-debt, and any new finding fails the gate.
- Fixed defects exposed by the new tools: separated `RateLimitAdmissionDenied` into its own declaration file, closed malformed public-contract key handling, made verified operation state narrowing explicit, made cart-planning terminal control flow provably non-returning, initialized request-fence identity state, and removed dead request-fence state.
- Split the WooCommerce internals monolith behind the same single application-facing adapter into five focused private collaborators for core reflection, session storage/cache, hook containment, cart identity/cloning, and persistent-cart projection. Added architecture escape checks and size/cohesion bounds.
- Hardened the cart-write boundary so promotion version, fence/storage capability, active core topology, and durable authority are proved before lock reacquisition or request-local Woo mutation; mutating adapter/session methods repeat the promotion check. Added independent future-version structural-drift coverage while preserving read-only behavior for unpromoted releases and exact-checksum compatibility-matrix promotion.
- Hardened runtime readiness into a schema-v2 proof/attempt state machine. An administrator recheck retains an unexpired proof while active, rejects fresh concurrent attempts, fences stale or configuration-old attempts, and cannot publish after supersession.
- Added a closed provider/probe failure taxonomy: transient timeout, network, quota, upstream, response-size, and interruption failures preserve a valid proof; authentication, model, service/billing, minimal-contract/precondition, and malformed minimal-response contradictions revoke it. Exact option read-back and fail-closed revocation prevent stale cache authority.
- Bound proof identity to the effective provider configuration, a monotonic configuration epoch, and the complete version-2 access/echo wire contract. Added deterministic fake-provider modes and packaged-promotion evidence proving transient preservation, deterministic revocation, and exact two-request recovery.
- Sealed model-authored follow-up authority behind the exact sole `respond_follow_up` call from a current-turn model-step capability bound to the active context, lease fence, model round, complete current-turn digest, recent intent history, and pending clarification. Removed primitive question constructors and broad hydration, added a closed self-verifying private evidence envelope with fixed tool identity, confined entity decoding to trusted commerce facts, and invalidated obsolete unpublished question state under conversation schema 5.
- Closed every plugin-owned REST response boundary under public contract version 3. Boot, turn, health, privacy export/delete, administrator readiness, and error responses now use endpoint-specific typed projectors and a bounded PHP validator generated from the same Draft 2020-12 schema as the browser contract; the generic associative-array success emitter was removed, unknown nested fields fail closed, and privacy export uses explicit allowlist projection instead of recursive filtering.
- Completed resilient browser continuity across admission identity, continuity credentials, conversation fencing, boot coordination, pending-turn identity, and exact retry envelopes. `localStorage` and `sessionStorage` are now accessed only through one verified boundary that degrades coherently to current-document memory on unavailable access, read/write rejection, failed verification, corrupt data, or failed cleanup; chat and exact same-document retry remain available while reload and cross-tab continuity are explicitly reduced.
- Reconciled items 1–8 onto one cumulative branch and restored the artifact-first packaged-plugin promotion lane without reintroducing retired readiness, question-authority, or exact-version architecture. The gate now requires exact local plugin and WooCommerce packages, records both checksums, verifies installed bytes, and certifies each `promotion_tested` WooCommerce release independently.
- Replaced the exact WooCommerce patch equality check with a closed `>=10.9.4 <11.0.0` compatibility policy that distinguishes promotion-tested releases from capability-gated future 10.x releases and rejects malformed, older, prerelease, and 11.x versions. Unpromoted releases remain read-only for cart operations.
